# string和stringbuilder的区别

  1. 不可变性 string：是不可变类型。一旦创建了一个string对象，其内容就不能被改变。当你对string进行拼接、替换等操作时，实际上是创建了一个新的string对象，而原来的对象会被垃圾回收。 StringBuilder：是可变类型。你可以对StringBuilder对象的内容进行修改，而无需创建新的对象。它内部维护了一个可变的字符数组，当需要改变内容时，直接在这个数组上进行操作。
  2. 性能表现 string：由于每次操作都会创建新对象，频繁的字符串操作会导致大量的内存分配和垃圾回收，从而影响性能。特别是在循环中进行字符串拼接时，性能问题会更加明显。 StringBuilder：因为它是可变的，所以在进行大量的字符串操作时，性能要比string好很多。它通过预先分配一定大小的缓冲区，减少了内存分配和复制的次数。
  3. 内存使用 string：由于每次操作都会创建新对象，会占用较多的内存空间，尤其是在处理大量字符串拼接时，会导致内存碎片的产生。 StringBuilder：通过预先分配缓冲区，可以更有效地管理内存。当缓冲区不足时，它会自动扩容，但扩容的次数相对较少，从而减少了内存的浪费。
  4. 适用场景 string：适用于字符串操作较少、字符串内容相对固定的场景，例如简单的字符串赋值、比较等操作。 StringBuilder：适用于需要进行大量字符串拼接、插入、删除等操作的场景，例如生成动态的HTML页面、日志记录等。

# stringbuilder底层实现原理

  1. 内部数据结构 StringBuilder 内部使用一个字符数组（char[]）来存储字符串内容。当你创建一个 StringBuilder 对象时，会为这个字符数组分配一定的初始容量。
  2. 动态扩容机制 当向 StringBuilder 中添加的字符数量超过了当前字符数组的容量时，StringBuilder 会自动进行扩容。扩容的过程如下：
  • 计算新的容量：通常新容量是原来容量的两倍，但也有一些特殊情况和优化策略。
  • 创建新的字符数组：根据新的容量创建一个新的字符数组。
  • 复制原有内容：将原字符数组中的内容复制到新的字符数组中。
  • 释放原字符数组：原字符数组会被垃圾回收。

# struct和类的区别

  1. 类型本质 struct：属于值类型。值类型的变量会直接存储其数据，在栈上分配内存。当把一个struct变量赋值给另一个struct变量时，实际上是复制了数据。 类：属于引用类型。引用类型的变量存储的是对象的引用，对象本身在堆上分配内存。当把一个类的对象赋值给另一个变量时，只是复制了引用，两个变量指向同一个对象。
  2. 实例化方式 struct：可以不使用new关键字进行实例化，不过此时所有字段必须在使用前手动初始化。 -类：必须使用new关键字来创建对象实例，若不创建，引用变量的值为null。
  3. 继承性 struct：不支持继承，不过可以实现接口。 -类：支持继承，一个类可以继承自另一个类，并且可以实现多个接口。
  4. 析构函数 struct：不支持析构函数。 类：支持析构函数，用于在对象被垃圾回收之前执行清理操作。
  5. 默认构造函数 struct：有一个隐式的无参构造函数，它会将所有字段初始化为默认值。你不能为struct定义无参构造函数，但可以定义带参数的构造函数。 类：如果没有定义任何构造函数，编译器会提供一个默认的无参构造函数。若定义了带参数的构造函数，默认无参构造函数将不再提供。
  6. 用途场景 struct：适合用于表示轻量级的数据结构，如点、矩形、颜色等，因为值类型的操作通常比引用类型更高效。 类：适合用于表示复杂的对象，需要继承、多态等特性的场景。

# const和readonly的区别

  1. 编译时与运行时赋值 const：属于编译时常量，其值必须在声明时就被指定，并且这个值在编译阶段就会被确定下来。在编译过程中，编译器会直接用常量的值替换代码里对该常量的引用。 readonly：属于运行时常量，它的值可以在声明时指定，也能在构造函数里进行赋值。一旦赋值之后，就不能再更改。
  2. 数据类型限制 const：仅能用于值类型（像 int、double、bool 等）和字符串类型。因为这些类型的值在编译时就能确定。 readonly：可以用于任何类型，包括引用类型。这是因为它的值是在运行时确定的，所以可以引用任何类型的对象。
  3. 静态与实例 const：隐式地是静态成员，所以不需要使用 static 关键字来修饰。不能通过实例来访问 const 成员，而要通过类名来访问。 readonly：既可以是静态成员（使用 static readonly 修饰），也可以是实例成员。静态 readonly 成员通过类名访问，实例 readonly 成员通过实例访问。
  4. 可变性 const：一旦定义之后，其值在整个程序的生命周期内都不能改变，具有高度的不可变性。 readonly：虽然赋值后不能再更改，但可以在不同的构造函数调用时赋予不同的值（对于实例 readonly 成员），或者在类的静态构造函数里为静态 readonly 成员赋值。

# 引用类型和值类型

变量的数据类型可以分为引用类型和值类型 内存分配

  • 值类型：在栈上分配内存，栈的分配和释放速度较快，适合存储简单的数据。
  • 引用类型：对象在堆上分配内存，引用在栈上分配内存。堆的分配和释放相对较慢，但可以存储复杂的数据结构。 赋值行为
  • 值类型：赋值时复制值。
  • 引用类型：赋值时复制引用。 生命周期
  • 值类型：其生命周期与其所在的作用域相关，当作用域结束时，值类型变量会被自动销毁。
  • 引用类型：对象的生命周期由垃圾回收机制管理，当没有引用指向对象时，对象会被垃圾回收器回收。

# 装箱和拆箱

装箱指的是把值类型转换为引用类型。在进行装箱操作时，会在堆上分配一块内存，用于存储值类型的数据，接着把值类型的数据复制到这块内存中，最后返回一个指向该内存的引用。

拆箱是将引用类型转换为值类型。在拆箱时，首先要检查引用类型的对象是否确实是由某个特定值类型装箱而来，若检查通过，就把堆上存储的值复制到值类型变量中。

# 堆和栈

栈是一种后进先出（LIFO）的数据结构，用于存储方法调用的上下文信息和值类型的变量。当一个方法被调用时，会在栈上为该方法创建一个栈帧（Stack Frame），栈帧包含了方法的局部变量、参数、返回地址等信息。 存储内容

  • 局部变量：方法内部定义的值类型变量，如int、double、struct等，会直接存储在栈上。
  • 方法调用信息：包括方法的返回地址、参数等。 内存分配与释放
  • 分配：当方法被调用时，会在栈上为该方法的局部变量和参数分配内存。栈的分配速度非常快，因为只需要移动栈指针。
  • 释放：当方法执行完毕后，对应的栈帧会被自动销毁，栈指针会回退，释放栈上的内存。这种自动释放内存的方式避免了内存泄漏的问题。

堆是一块用于动态分配内存的区域，用于存储引用类型的对象。与栈不同，堆上的内存分配和释放需要程序员或垃圾回收器（Garbage Collector，GC）来管理。 存储内容

  • 引用类型对象：如class、interface、array等类型的对象，会在堆上分配内存。
  • 对象的字段：对象的字段也存储在堆上。 内存分配与释放
  • 分配：当使用new关键字创建一个引用类型的对象时，会在堆上为该对象分配内存。堆的分配速度相对较慢，因为需要在堆中寻找合适的空闲内存块。
  • 释放：当一个对象不再被引用时，它所占用的内存不会立即释放，而是由垃圾回收器在合适的时机进行回收。垃圾回收器会定期检查堆上的对象，标记那些不再被引用的对象，并释放它们所占用的内存。

# 托管代码和非托管代码

托管代码是指由.NET 运行时环境（CLR，Common Language Runtime）管理的代码。C## 作为一种主要运行在.NET 平台上的语言，大部分代码都是托管代码。CLR 为托管代码提供了一系列的服务，包括内存管理、类型安全检查、异常处理等。 非托管代码是指不依赖于.NET 运行时环境，直接在操作系统上运行的代码

可空类型的本质C# 中的可空类型实际上是System.Nullable<T>结构体的实例，其中T代表基础值类型。Nullable<T>结构体是一个泛型结构体，它在System命名空间中定义，通过封装基础值类型，为其赋予了可以表示null的能力。 可空类型是值类型吗？ 可空类型属于值类型。本质是结构体

# 记录(record)

在 C# 9.0 及之后的版本中引入了记录（record）这一特性，它是一种特殊的引用类型，主要用于以不可变的方式表示数据。 复制和修改记录（with 表达式）记录类型提供了 with 表达式，用于创建一个新的记录实例，该实例基于现有的记录实例，但可以修改部分属性的值 继承和多态 记录可以继承自其他记录，但不能继承自普通类，也不能被普通类继承。 应用场景

  • 数据传输对象（DTO）：在不同层之间传输数据时，记录的不可变性和值相等性比较特性非常有用。
  • 函数式编程：不可变的数据结构符合函数式编程的理念，记录可以很好地用于函数式风格的代码中。
