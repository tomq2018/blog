在 .NET Core 里，中间件是处理 HTTP 请求和响应的关键组件，它能够对请求进行预处理，对响应进行后处理。

基本概念 中间件本质上是一个可以处理 HTTP 请求和响应的软件组件，多个中间件可以组合成一个请求处理管道。当有 HTTP 请求到达时，请求会依次经过管道中的每个中间件，每个中间件都有机会对请求进行处理，并且可以决定是否将请求传递给下一个中间件，或者直接返回响应。

中间件的工作原理 请求处理管道就像一个链条，每个中间件都是链条上的一环。请求从管道的一端进入，依次经过各个中间件，最终到达管道的另一端。如果某个中间件返回了响应，那么响应会沿着相反的方向返回，依次经过之前的中间件。

# 中间件的类型

内置中间件 .NET Core 提供了许多内置的中间件，以下是一些常见的内置中间件及其作用：

  • 静态文件中间件：用于处理静态文件请求，比如 HTML、CSS、JavaScript 等文件。使用 app.UseStaticFiles() 方法可以启用该中间件。
  • 路由中间件：负责将请求路由到相应的控制器和动作方法。使用 app.UseRouting() 和 app.UseEndpoints() 方法来配置路由。
  • 认证中间件：用于处理用户认证和授权。可以使用 app.UseAuthentication() 和 app.UseAuthorization() 方法启用认证和授权中间件。 自定义中间件 除了使用内置中间件，你还可以创建自定义中间件来满足特定的需求。自定义中间件通常是一个实现了特定接口或遵循特定约定的类。
using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using System.Threading.Tasks;

// 自定义中间件类
public class CustomMiddleware
{
    private readonly RequestDelegate _next;

    public CustomMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 请求处理前的逻辑
        await context.Response.WriteAsync("请求进入基于类的自定义中间件\n");

        // 调用下一个中间件
        await _next(context);

        // 请求处理后的逻辑
        await context.Response.WriteAsync("响应离开基于类的自定义中间件\n");
    }
}

// 扩展方法，方便注册中间件
public static class CustomMiddlewareExtensions
{
    public static IApplicationBuilder UseCustomMiddleware(this IApplicationBuilder builder)
    {
        return builder.UseMiddleware<CustomMiddleware>();
    }
}

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// 注册自定义中间件
app.UseCustomMiddleware();

app.Run(async (context) =>
{
    await context.Response.WriteAsync("Hello, World!\n");
});

app.Run();

# 中间件的注册顺序

中间件的注册顺序非常重要，因为请求会按照中间件的注册顺序依次经过各个中间件。通常，应该按照以下顺序注册中间件： 1.异常处理中间件：放在最前面，以便捕获后续中间件中可能发生的异常。 2.静态文件中间件：在路由中间件之前注册，以便处理静态文件请求。 3.路由中间件：负责将请求路由到相应的控制器和动作方法。 4.认证和授权中间件：在路由中间件之后注册，以便对路由后的请求进行认证和授权。 5.自定义中间件：根据具体需求，在合适的位置注册自定义中间件。

# 中间件和过滤器的区别

作用层面

  • 中间件 中间件主要负责处理整个 HTTP 请求和响应的生命周期，它处于请求处理管道的底层，在请求到达应用程序的具体处理逻辑之前和响应返回客户端之前进行操作。它可以对请求进行预处理，例如记录请求日志、处理跨域请求、解析请求体等；也可以对响应进行后处理，例如压缩响应内容、添加响应头信息等。
  • 过滤器 过滤器主要用于在控制器动作执行的前后进行特定操作，它更侧重于应用程序的业务逻辑层面。过滤器可以对控制器的输入参数进行验证、在动作执行前后进行日志记录、处理异常、进行授权验证等。

使用场景

  • 中间件
    • 全局请求处理：对所有请求进行统一处理，例如全局的日志记录、请求缓存、错误处理等。
    • 协议级别的处理：处理与 HTTP 协议相关的操作，如 HTTPS 重定向、跨域资源共享（CORS）配置等。
    • 请求的早期处理：在请求进入应用程序的具体处理逻辑之前进行预处理，如请求的解析、身份验证的初步检查等。
  • 过滤器
    • 控制器和动作的特定处理：针对特定的控制器或动作进行处理，例如对某些控制器的输入参数进行验证、对某些敏感操作进行授权检查等。
    • 动作执行前后的逻辑：在控制器动作执行前后添加额外的逻辑，如记录动作执行时间、在动作执行前进行数据初始化等。
    • 异常处理：捕获和处理控制器动作中抛出的异常，提供统一的异常处理机制。

实现方式

  • 中间件

    • 基于委托的中间件：使用 RequestDelegate 委托来处理请求，通过 app.Use 方法注册。
    • 基于类的中间件：创建一个实现特定接口的类，通过 app.UseMiddleware 方法注册。

  • 过滤器

    • 内置过滤器：.NET Core 提供了多种内置过滤器，如 AuthorizeFilter 用于授权验证、ExceptionFilter 用于异常处理等，可以通过在控制器或动作上添加特性来使用。
    • 自定义过滤器：创建一个实现特定过滤器接口（如 IActionFilter、IExceptionFilter 等）的类，然后在控制器或动作上应用该过滤器。

执行顺序

  • 中间件：中间件按照注册的顺序依次执行，请求从第一个中间件开始，依次经过后续的中间件，直到到达请求处理的终点。响应则按照相反的顺序返回，依次经过之前的中间件。
  • 过滤器：过滤器的执行顺序由其类型和注册方式决定。不同类型的过滤器（如授权过滤器、资源过滤器、动作过滤器等）有固定的执行顺序，同一类型的过滤器可以通过设置 Order 属性来指定执行顺序。
